## F9 관리자 창

탐험관 화면에서 **F9** 를 누르면 열립니다. (F9 가 없는 크롬북·휴대폰: 주소 끝에 `#admin` 을 붙여 열기)
관리자 계정으로 구글 로그인해야 열립니다. 관리자 명단은 아래 "관리자 명단 바꾸기" 참고.

| 기능 | 하는 일 | 반영 |
|---|---|---|
| ⚡ 바로 반영 | 제출 폴더를 지금 확인해 새 파일을 가져옴 | 1~2분 (안 눌러도 10분마다 자동) |
| 📝 파일 이름 규칙 | 학생에게 안내할 제출 규칙 | — |
| 📂 올라가지 않은 파일 | 이름 규칙이 틀린 파일에 **학번·이름을 정해 게시**, 또는 '다시 제출' 목록에서 지우기 | 게시는 '바로 반영' 후, 지우기는 즉시 |
| 🧭 웹앱 목록 | 학번·이름·제목·분류 **바꾸기**, **삭제(내리기)**·되살리기 | 즉시 (되살린 앱의 파일은 '바로 반영' 후) |
| 💡 업그레이드 요청 관리 | 부적절한 요청 지우기 | 즉시 |

- **삭제는 탐험관에서 내리는 것**입니다. 드라이브 파일과 추천·요청 기록은 그대로 남고 언제든 되살릴 수 있습니다. (드라이브 파일은 제출 폴더 소유 계정만 지울 수 있습니다.)
- 관리자 창에서 바꾼 내용은 Firestore `socialAdmin/overrides` 에 저장되고, 다음 동기화 때 `site/games.json` 에도 반영됩니다.

## 학생 제출 규칙 (관리자 창에도 같은 내용이 있음)

1. 파일 이름 끝이 `학번이름.html` — 예) `세계수도퀴즈 - 3115홍길동.html`. 학번은 4자리(학년·반·번호2).
2. 구글 설문으로 내면 파일 이름 뒤에 ` - 응답자이름` 이 붙으므로, 계정 이름이 '학번이름'이면 자동으로 맞춰짐.
3. AI 대화 화면을 통째로 저장한 파일은 안 됨 → 탐험관 맨 위 "다시 제출이 필요해요"에 이름이 뜸.
4. 고친 버전은 새 파일을 그냥 올리면 됨(추천·요청 유지, `UPDATE` 배지). 다른 앱은 여러 개 가능(`학번-2` …).

## 추천·업그레이드 요청

- 학교 계정(`@dongshin.ms.kr`)만 가능. 추천은 앱마다 1번(다시 누르면 취소), 요청은 300자까지 여러 번.
- 요청에는 이름이 가운데 가려져 표시됩니다(예: 홍○동). 본인과 관리자만 지울 수 있습니다.
- 저장 위치: Firestore `socialLikes`, `socialRequests` (게임·웹앱 스토어와 같은 Firebase 프로젝트, 칸만 다름).

## 처음 한 번 설정 (교사가 직접)

### 1) 보안 규칙 올리기
`D:\2026game\firestore.rules` 전체를 Firebase 콘솔 → 데이터베이스 및 스토리지 → Firestore → **규칙** 에 붙여넣고 **게시**. (세 사이트 규칙이 한 파일에 있음. 터미널 `firebase login` 은 회사 계정 로그인 화면에서 막힐 수 있어 콘솔 방법을 씀)

### 2) 관리자 명단 만들기 / 바꾸기
명단은 코드에 넣지 않고 Firestore 비공개 문서에 둡니다(학생·외부인은 읽을 수 없음).
Firebase 콘솔 → Firestore → **데이터** → `+ 컬렉션 시작`
- 컬렉션 ID: `socialConfig`
- 문서 ID: `admins`
- 필드: `emails` / 유형 **array** / 값: 관리자 이메일을 하나씩 **소문자로** 추가 (string)

관리자를 바꿀 때는 이 `emails` 배열만 고치면 바로 적용됩니다.

### 3) 승인된 도메인
Firebase 콘솔 → Authentication → 설정 → 승인된 도메인 → `dongshin-social-2026.vercel.app` 추가.

### 4) '바로 반영'용 GitHub 토큰
'바로 반영' 버튼은 Vercel 서버가 GitHub에 "지금 동기화해"라고 요청하는 방식이라 토큰이 필요합니다.
1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
2. Repository access: **Only select repositories** → `2026social`
3. Permissions → Repository permissions → **Actions: Read and write** (다른 권한은 필요 없음)
4. 만든 토큰을 Vercel → 프로젝트 `dongshin-social-2026` → Settings → Environment Variables 에 이름 `GITHUB_TOKEN` 으로 저장 → 다시 배포
토큰 만료일이 지나면 '바로 반영'만 멈춥니다(10분마다 자동 동기화는 계속 동작). 새로 만들어 같은 이름으로 바꿔 넣으면 됩니다.

## 문제가 생겼을 때

| 증상 | 해결 |
|---|---|
| 관리자 창이 "관리자 계정이 아니에요" | `socialConfig/admins` 의 `emails` 에 그 이메일(소문자)이 있는지, 규칙을 게시했는지 확인 |
| '바로 반영'이 "GITHUB_TOKEN 이 설정되지 않았어요" | 위 4) 설정 후 Vercel 재배포 |
| '바로 반영'이 "GitHub 응답 401/403" | 토큰 만료 또는 권한 부족(Actions: Read and write) |
| 동기화 실패 "관리자 수정값을 읽지 못함" | 보안 규칙이 게시되지 않음 → 1) |
| 로그인 팝업 오류 `unauthorized-domain` | 위 3) |
| 새 웹앱이 30분 넘게 안 올라옴 | 관리자 창 '바로 반영', 또는 Actions 페이지 확인 |

